## Getting Started

### Q: How do I set up the dev environment?
1. Clone the repo and `cd tPAAW`.
2. Run `npm install` to install dependencies.
3. Copy `.env.example` to `.env` and fill in required values (see below).
4. Start the dev server: `npm run dev` (default port 3000).
5. Open `http://localhost:3000` in your browser.

### Q: What environment variables do I need?
| Variable | Description | Example |
|----------|-------------|---------|
| `LLM_API_KEY` | API key for the external LLM service (e.g., OpenAI) | `sk-xxxxxxxxxxxxxxxxxxxx` |
| `LLM_MODEL` | Model name to use | `gpt-4` |
| `PAAW_STORAGE_PATH` | Path to the `.paaw/` knowledge directory | `./.paaw` |
| `NEXT_PUBLIC_APP_URL` | Public URL of the app (for API calls) | `http://localhost:3000` |
| `JWT_SECRET` | Secret for signing auth tokens | `your-secret-key-here` |

### Q: How do I configure the LLM for AI agents?
Set `LLM_API_KEY` and `LLM_MODEL` in `.env`. The platform uses these to communicate with the LLM service. Ensure your API key has sufficient quota and the model supports agent‑style prompting.

## Common Issues

### Q: I'm getting Error Code 40001, what do I do?
**Validation error** — your request had invalid input.  
Check the error message for which field is wrong. Common causes: missing required fields, invalid UUID format, or values out of range.  
→ Runbook: `../runbook/40001.md`

### Q: I'm getting Error Code 40401, what do I do?
**Crew not found** — the `crewId` you provided does not exist.  
Verify the crew ID is correct and that the crew was created (use `GET /api/v1/agents/crew/{crewId}/status`). If you just created it, wait a moment for the creation to complete.  
→ Runbook: `../runbook/40401.md`

### Q: I'm getting Error Code 40901, what do I do?
**Task already assigned** — the `taskId` you provided is already assigned to another crew.  
Use a different `taskId` (each task must be unique). You can also cancel the existing assignment via `POST /api/v1/agents/crew/{crewId}/cancel`.  
→ Runbook: `../runbook/40901.md`

### Q: I'm getting Error Code 40902, what do I do?
**Crew not in running state** — you tried to cancel a crew that is not currently running.  
Only crews with status `running` can be cancelled. Check the crew status via `GET /api/v1/agents/crew/{crewId}/status`.  
→ Runbook: `../runbook/40902.md`

### Q: I'm getting Error Code 50001, what do I do?
**Internal server error** — something went wrong on the server.  
Check the server logs (`git log` or `tail -f logs/app.log`). Common causes: LLM API timeout, file system permission issues, or unhandled exceptions. Restart the server and retry.  
→ Runbook: `../runbook/50001.md`

### Q: The API returns 500, what should I check?
1. **LLM API key** – verify `LLM_API_KEY` is valid and has quota.
2. **File permissions** – ensure the `.paaw/` directory is writable.
3. **Server logs** – look for stack traces or error messages.
4. **Network** – ensure the server can reach the LLM API.
5. **Restart** – sometimes a temporary glitch clears on restart.

### Q: Changes aren't showing up after restart
Common cause: **browser cache** (especially for static assets).  
Fix: hard refresh (Cmd+Shift+R on Mac, Ctrl+Shift+R on Windows).  
If the issue persists, clear the `temp/` directory and rebuild: `rm -rf temp/* && npm run build && npm run dev`.

## Development

### Q: How do I add a new API endpoint?
1. Add a new route in the API server (likely `src/routes/` or `packages/api/routes/`).
2. Define the request/response contract in `.paaw/specs/api-contract.md`.
3. Implement the handler, using existing tools (e.g., `read_feature_map`, `write_issue`).
4. Update the `ARCHITECTURE.md` dependency graph if needed.  
→ See `ARCHITECTURE.md` for module structure.

### Q: How do I add a new AI agent?
1. Register the agent in the domain‑agent‑registry (likely `src/agents/registry.ts`).
2. Define the crew JSON in `.paaw/crews/` (e.g., `night-shift.crew.json`).
3. Assign tool permissions (which `.paaw/` API tools the agent can use).
4. Update the Agent Memory panel to display the new agent.  
→ See `ARCHITECTURE.md` for agent/crew structure.

### Q: Where should I put shared utilities?
Place shared utilities in `src/lib/` or `packages/shared/src/`.  
Examples: `src/lib/llm.ts` for LLM calls, `src/lib/validation.ts` for input validation.  
Keep them small and single‑purpose. Import them directly in route handlers or agent tools.

### Q: How do I run tests?
- **Unit tests**: `npm run test` (runs all `.test.ts` files).
- **E2E tests**: `npm run test:e2e` (requires server running).
- **Single file**: `npx jest path/to/file.test.ts`.
- **Coverage**: `npm run test:coverage` (outputs to `coverage/`).

## Night Shift 是怎麼運作的？我要怎麼啟動？
**Category:** features

Night Shift 是 EM Dashboard 上的自動化功能。啟動後，6 個 AI agent（architect、developer、tester、doc-writer、qa、helpdesk）會平行掃描 git 變更並執行任務。

啟動方式：
1. 打開 EM Dashboard（右側面板）
2. 可以在「從」日期選擇器指定要掃描哪一天以來的 git 變更（預設是今天）
3. 點「🌙 Night Shift」按鈕啟動

啟動後 Dashboard 會即時顯示每位 agent 的進度。完成後會產生 Night Shift Report，包含各 agent 的工作摘要。

如果需要指定掃描範圍而非只有今天，可以在啟動前調整日期選擇器。

## EM 自動調度和 Night Shift 有什麼不同？
**Category:** features

EM 自動調度（🚀 EM 自動調度）和 Night Shift（🌙 Night Shift）是兩種不同的運作模式：

**EM 自動調度（EM Auto Dispatch）**
- 由 Engineering Manager agent 規劃工作計劃、逐一派發任務給各 agent
- 使用 SSE（Server-Sent Events）即時串流進度
- 完成後會產生一份「隔天報告」
- 適合仔細規劃的批次工作

**Night Shift**
- 6 個 agent 平行獨立工作，EM 不介入調度
- 使用 POST 請求啟動，由 polling 取得進度
- 適合快速掃描和處理大量變更
- 日期選擇器可決定要掃描哪一段時間的 git 變更

兩者完成後都會在 Dashboard 的聊天區域顯示摘要，並且都可以透過「Commit & Push」按鈕將 agent 的變更提交。

## Coding IDE 的 Git 面板有新的 Commit/Push/Pull 按鈕，要怎麼用？
**Category:** features

Coding IDE 的 Git 面板（點擊側邊欄的 Git 圖示）現在有完整的 Git 操作按鈕：

**基本操作**
- ⬇ Pull — 拉取遠端變更
- ⬆ Push — 推送本地變更到遠端
- ✅ Commit All — 自動 stage 所有變更並 commit

**如何 Commit & Push**
1. 在 Git 面板中，檢查 Status 頁籤確認變更內容
2. 在「Commit message...」輸入框中輸入 commit 訊息
3. 按 Enter 或點「✅ Commit All」按鈕
4. 確認成功後按「⬆ Push」推送

**Git Review（AI Code Review）**
- 在 Review 頁籤，點「New Review」按鈕
- AI 會根據 git diff 產生 code review 意見
- ⚠️ 注意：目前 Node.js 25 環境下 AI Review 功能有已知問題（chatRes.body.on 非函式），會回傳基本分析而非完整 AI review。

**注意事項**
- 操作時會顯示即時狀態回饋在面板頂部
- 提交成功或失敗都會有明確訊息

## AI Review 顯示「AI review 不可用 (chatRes.body.on is not a function)」怎麼辦？
**Category:** troubleshooting

這是在 Node.js 25（或其他較新版本）上的已知問題。Node.js 18+ 的內建 `fetch()` API 回傳的是 Web `ReadableStream`，但程式碼用了 `chatRes.body.on("data")` — 這是 Node.js stream（IncomingMessage）的寫法，不是 Web stream 的寫法。

**目前影響**：無法產生真正的 AI review，只會回傳基本的 diff 分析。

**預計修復**：Developer 團隊已記錄此問題（ISS-001），需要將 `chatRes.body.on("data")` 改為 `for await (const chunk of chatRes.body)` 或 `chatRes.body.getReader()`。

**暫時替代方案**：可以直接在聊天中請 AI agent 幫忙 review diff。
