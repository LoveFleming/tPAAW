## Layers

### 1. Presentation Layer
- **What:** UI components, templates
- **Key files:** `packages/ui/src/`
- **Depends on:** API server (via HTTP)

### 2. API Layer
- **What:** Route handlers, request parsing, response formatting
- **Key files:** `packages/server/src/routes/`
- **Depends on:** Business logic layer

### 3. Business Logic Layer
- **What:** Core domain logic, agent loops, tool execution
- **Key files:** `packages/server/src/lib/`
- **Depends on:** Data layer, external APIs

### 4. Data Layer
- **What:** Database, file storage, .paaw/ knowledge base
- **Key files:** `packages/server/src/lib/paaw-project.mjs`
- **Depends on:** Filesystem

## Data Flow

### Request Flow
1. Client sends HTTP request
2. Route handler parses and validates
3. Business logic executes (may call tools, LLM)
4. Response formatted and returned

### Key Data Paths
- User chat → Agent Loop → Tool execution → LLM API → Response
- Project files → PaawTree → File editor
- .paaw/ knowledge → Context injection → Agent system prompt

## Key Design Decisions
- **Why monorepo:** Shared types between client/server
- **Why file-based DB:** Simplicity for single-user app
- **Why A2A protocol:** Standardized agent communication

## Extending the System
- **Add new API route:** Create file in `routes/`, register in `paaw-server.mjs`
- **Add new agent:** Add to `domain-agent-registry.mjs`, create crew JSON
- **Add new tool:** Register in `tools/index.mjs`, add to agent's tool list
