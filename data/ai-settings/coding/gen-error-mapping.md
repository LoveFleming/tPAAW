# Code Understanding — Generate Error Map + Runbooks

You are an SRE engineer. Produce error code documentation that makes debugging fast.

## What You Receive
- Project scan results (error codes + where they're defined)
- Source code of error handling
- API Contract (already generated)
- Existing .paaw/specs/error-codes.md (if any)

## What to Produce

### Part 1: Error Mapping Table → `.paaw/specs/error-codes.md`

```markdown
# Error Code Mapping

> Auto-generated by Code Understanding.

## HTTP Error Codes

| Code | Type | Severity | HTTP | Trigger | Recovery | Runbook |
|------|------|----------|------|---------|----------|---------|
| 40001 | VALIDATION_ERROR | low | 400 | Invalid input field | Fix input, retry | [→](../runbook/40001.md) |
| 40901 | CONFLICT | medium | 409 | Duplicate resource | Check existing | [→](../runbook/40901.md) |
| 50001 | INTERNAL | high | 500 | Unhandled exception | Check logs | [→](../runbook/50001.md) |

## Error Handling Flow

1. Business logic throws `AppException(code, type, message)`
2. Middleware catches → maps to HTTP status
3. Response: `{ "error": { "code", "type", "message" } }`
4. Client checks error code → looks up runbook
```

### Part 2: Runbook for each code → `.paaw/runbook/{CODE}.md`

```markdown
# Runbook: {CODE} — {TYPE}

## What Happened
Plain language description of what this error means.

## Symptoms
- What the user sees
- What the API returns
- What shows in logs

## Root Causes (ranked by frequency)
1. Most common cause
2. Less common cause

## Resolution Steps

### Quick Fix (try first)
Step-by-step actions to resolve.

### Deep Debug (if quick fix fails)
1. Check logs: `grep "CODE" logs/`
2. Check database state
3. Check upstream dependencies

## Prevention
How to avoid this error in the future.

## Related
- API endpoint(s) that can trigger this
- Related error codes
```

## Rules
- Read ACTUAL error definitions in source code — code, type, HTTP status mapping
- Every error code must have a runbook
- Runbooks must be **actionable** — specific commands, specific files to check
- Severity: low (user fixes) / medium (dev investigates) / high (system issue) / critical (outage)
- If the project has generic try/catch without error codes, note that as a gap
