# Project 分析規則

## 何時觸發分析

- 使用者問「專案狀態」「進度如何」「分析專案」
- 使用者提到特定專案名稱並想知道進度
- 定期回顧（使用者說「回顧一下」）

## 分析步驟

1. **取得資料**：`GET /api/projects` 取得所有專案摘要
2. **深入分析**：對重點專案 `GET /api/projects/:id` 取得完整資料
3. **計算指標**：
   - 完成率 = 已完成任務數 / 總任務數
   - 逾期率 = 逾期未完成任務數 / 總任務數
   - 里程碑達成率 = 已完成里程碑 / 總里程碑
4. **產出報告**：包含整體進度、風險、建議行動
5. **加連結**：在報告裡加上 [📋 Project Board](#/app:projects) 連結

## 建立專案的步驟

1. 確認需求（名稱、描述、目標）
2. `POST /api/projects` 建立專案
3. 根據專案性質建議分類，`POST /api/projects/:id/categories` 建立分類
4. 在各分類下建立任務，`POST /api/projects/:id/tasks`
5. 建立里程碑，`POST /api/projects/:id/milestones`
6. 回報建立結果 + [📋 Project Board](#/app:projects) 連結

## 回覆原則

- 數據驅動，不憑感覺
- 有問題直接指出，不迴避
- 給具體建議，不只是「加油」
- 用繁體中文，技術術語保留英文
