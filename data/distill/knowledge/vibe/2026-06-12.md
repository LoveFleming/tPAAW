# 💡 知識蒸餾：Pocket 應用程式 API 資料標準化

## 1. 任務摘要
本次任務主要針對 `Pocket` 應用程式進行資料接口修正與前端重構。具體做了兩件事：
*   修正後端 `/api/notes` GET 請求的資料格式，統一欄位名稱。
*   更新（重新建置/注入）前端 `apps/pocket/app.html` 檔案，以配合新的資料格式。

## 2. 關鍵決策
*   **後端優先標準化**：決定採用「後端統一正規化資料」的策略。AI 評估後認為最簡單的做法是由 Server 端處理資料轉換，確保前端接收到的資料格式一致，無需讓前端去適應多種舊格式。

## 3. 技術要點
*   **開發工具與環境**：
    *   使用 `qwen` 模型的 CLI 工具。
    *   處於 **YOLO mode**（自動執行模式，AI 會直接修改檔案而無需逐步人工確認）。
*   **後端**：
    *   修改 `paaw-server.mjs` (Node.js / ESM 模組)。
    *   實作 `normalizeNote()` 函式來映射資料。
*   **前端**：
    *   框架：React (從日誌中的 `p.jsx`, `p.jsxs`, `children` 可看出)。
    *   樣式：Tailwind CSS (從 `bg-slate-50`, `rounded-lg`, `text-sm` 等特徵可知)。
    *   產物：直接修改/更新打包壓縮後的 HTML 檔案 (`data/apps/pocket/app.html`)。

## 4. 遇到的問題與解法
*   **問題**：資料庫或舊版程式碼中，筆記資料的欄位名稱不一致。有時是 `text` 或 `title`，狀態有時是布林值 `done`，有時是字串 `status`。
*   **解法**：在後端 `/api/notes` 路由中加入 `normalizeNote()` 處理函式，使用 JavaScript 的短路求值 提供預設值與映射：
    *   **內容統一**：`content = n.content || n.text || n.title || ""`
    *   **狀態統一**：`status = n.status || (n.done ? "done" : "active")`

*   成功重新生成/更新了 `apps/pocket/app.html` 前端頁面，支援顯示筆記內容、情緒回饋及完成/恢復按鈕等 UI 功能。

## 6. 可復用的模式
*   **資料正規化模式**：
    當面對不穩定或歷史遺留的資料結構時，在 API 出口處（後端）統一攔截並轉換欄位（`fallback chain: a || b || c || default`），保持前端程式碼的乾淨與穩定。
*   **AI Agent 工作流**：
