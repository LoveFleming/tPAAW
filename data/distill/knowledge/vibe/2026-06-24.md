## 知識蒸餾：AI Service Monitor 儀表板資料填充與前後端強化

### 1. 任務摘要
- **目標**：為一個名為「AI Service Monitor」的儀表板應用程式填充 100 筆真實的模擬資料，並修正/加強前端功能，使其能夠正常運作（濾波器、動態時間戳、圖表正確繪製）。
- **起因**：使用者希望測試該應用程式是否可用，要求從「萬用 API」塞入 100 筆資料。
- **最終成果**：成功生成 100 筆具現實模式的時序資料（涵蓋流量起伏、週末低谷、錯誤尖峰與相關延遲），並大幅更新 `app.html`，讓濾波器按鈕、標題時間戳、圖表繪製與表格取樣等功能皆能正常工作。

### 2. 關鍵決策
| 決策項目 | 選擇方案 | 理由 |
|----------|----------|------|
| 資料存儲位置 | 直接寫入 `data/app-data/ai-service-monitor.json`，而非逐一透過 API 寫入 | 一次性大量寫入效率高，且符合該架構（萬用 API 會靜態提供該 JSON 檔） |
| 資料生成方式 | 使用 Node.js 腳本在本機生成 100 筆仿真資料 | 速度快、可程式化控制真實感（時間模式、相關性） |
| 圖表更新策略 | 濾波切換時徹底 `destroy()` 舊圖表，再 `new Chart()` 重建 | 避免 Chart.js 記憶體洩漏與殘留圖表，確保圖表數據始終與濾波結果一致 |
| 表格顯示大量資料 | 自動取樣，最多顯示 24 行（取樣邏輯非單純每隔 n 行） | 提升渲染效能，同時保留代表性的資料點 |
| 濾波器行為 | 統一事件監聽（事件代理），依 `data-hours` 屬性過濾資料陣列 | 乾淨、可擴展，不需為每個按鈕綁定獨立 handler |

### 3. 技術要點
- **後端／資料層**：
  - 萬用 API 靜態提供 `data/app-data/` 下的 JSON 檔案，路徑對應為 `/api/app-data/{app-name}`。
  - 資料結構：每個資料點包含 `id`、`createdAt`（ISO 字串）、`hour`（人類可讀）、`success`、`fail`、`avg`、`p95`、`max`。
  - 資料生成腳本模擬了：
    - 白天流量高、夜間流量低
    - 週末流量明顯下降
    - 偶發錯誤尖峰與高延遲相關性
- **前端（app.html）**：
  - **技術棧**：原生 JavaScript + Chart.js
  - **濾波機制**：按鈕 `data-hours` 屬性設定時間範圍（1H=1, 6H=6, 24H=24, 7D=168, ALL=720），過濾 `createdAt` 在當前時刻之前指定小時內的資料。
  - **動態時間戳**：使用 `new Date().toLocaleString(...)` 於每次渲染時更新標頭 `#updatedTime`。
  - **圖表生命週期**：宣告全域 `charts` 物件儲存所有 Chart 實例，渲染前先執行 `destroy()` 避免重複建立。
  - **資料繫結**：`render()` 函數接收過濾後的資料，統一更新 KPI 卡片、四個圖表與表格。
- **工具**：Node.js、CLI 工具（`node -e` 腳本）、Vibe Coding 的 YOLO 模式。

### 4. 遇到的問題與解法
| 問題 | 解法 |
|------|------|
| **資料不存在**：初次執行時 `data/app-data/ai-service-monitor.json` 不存在，導致前端無資料 | 探勘伺服器程式碼 `paaw-server.mjs`，找到資料存放慣例，直接生成 JSON 檔案 |
| **圖表無法更新**：濾波切換時舊圖表殘留，或圖表數據未重新計算 | 改為在每次 `render()` 開始時對全域 `charts` 物件中的每個實例呼叫 `.destroy()`，再重新 `new Chart()` |
| **表格顯示問題**：原始程式碼僅顯示隔行取樣，無法應付 100 筆資料 | 改為自動取樣：若資料 >24 筆，則均勻選取 24 筆（確保頭尾包含），否則全部顯示 |
| **時間戳靜態**：標頭時間顯示固定時間，不是當前時間 | 在渲染時由 `new Date()` 動態產生，並設定 `Intl.DateTimeFormat` 格式化 |
| **濾波器無反應**：UI 上按鈕沒有綁定事件 | 加入事件代理監聽 `.filter-btn` 點擊，更新 active 樣式，並調用 `render(getFiltered())` |

### 6. 可復用的模式
| 模式 | 說明與適用場景 |
|------|----------------|
| **資料種子腳本** | 寫一個獨立 Node.js 腳本，參數化資料量、時間範圍與模擬模式，便於重複測試或 CI。 |
| **全域圖表管理器** | 使用 `charts = {}` 統一管理多個 Chart.js 實例，搭配 `destroy()` 重繪模式，適用於需要頻繁更新資料的儀表板。 |
| **事件代理濾波** | 在容器上監聽 `click` 事件，利用 `event.target.closest()` 與自訂屬性 `data-*` 統一處理不同濾波範圍，可擴充性高。 |
| **表格自動取樣** | 對於 >N 筆資料，使用均勻取樣演算法（保留首尾）渲染表格，提升大數據集的渲染效能與閱讀體驗。 |
| **動態時間戳更新** | 在 `render()` 入口處直接使用 `Date.toLocaleString()` 更新 UI，簡單且符合即時性要求。 |
| **專案探索流程** | 發現功能缺失時，先用 `grep` / `ListFiles` 探索架構，再 `ReadFile` 關鍵部分確認慣例，最後制定計劃。使用 TodoList 逐步實現。 |
| **模擬資料真實性** | 在生成腳本中加入時間模式（高低峰、週末）、隨機異常與相關性，讓測試結果更貼近真實情境。 |
