## 1. 概觀

AI Settings 是平台所有 AI 功能的**提示詞與執行設定的單一管理入口**：

- **各功能的系統提示詞檔案** — 9 個固定分類（chat、coding、skill-builder…），分類內 `.md` 檔案完全動態（可透過 UI/API 建立、編輯、刪除）
- **Agent 執行設定** — `agent-config.json`（maxTurns、各類 timeout）
- **Provider 供應商設定** — 讀寫 `data/config/providers.json`
- **使用者模型偏好** — 讀寫 `data/config/user.json` 的 `preferences`（per-feature model override）
- **Workspace 目錄** — 讀寫 `data/config/workspaces.json`（AI 可存取的目錄清單）

所有提示詞檔案落在 `data/ai-settings/`，由 context-engine（`packages/server/src/context-engine.mjs`）在每次 LLM 呼叫前組裝進 system prompt。

### 檔案組成

| 層 | 檔案 | 職責 |
| --- | --- | --- |
| Route | `packages/server/src/routes/ai-settings.mjs` | 單檔承載全部 14 個端點（見 §4） |
| UI | `packages/ui/src/pages/AISettingsPage.tsx` | 分類式提示詞編輯器（CRUD） |
| UI | `packages/ui/src/pages/SettingsPage.tsx` | 設定中心入口（AI 設定分頁之一） |
| 消費端 | `packages/server/src/context-engine.mjs` | `getAISettings()` 讀取分類檔案組裝 system prompt |

## 2. 使用指南（AI Settings）

### 2.1 進入方式

側邊欄 → **Settings（設定）** → AI 相關分頁，或直接開啟 AISettingsPage。左側為分類清單（含 icon 與描述），右側為該分類的檔案清單與編輯器。

### 2.2 九大分類

| 分類 | 目錄 | 內容 | 子分類 |
| --- | --- | --- | --- |
| 💬 Chat | `chat/` | 聊天助理的 identity、system-prompt、guardrails、core-rules、tool-rules、reply-rules、paaw-context | — |
| 👤 Crew | `crew/` | AI Crew 的 skill 執行規則 | — |
| 🔨 Skill Builder | `skill-builder/` | 技能建構器的產出規則與提示 | `build/`、`test/` |
| 📦 App Builder | `app-builder/` | App 建構器的產出規則 | — |
| 📝 Notes | `notes/` | AI 筆記整理規則 | — |
| 🧠 Mind Map | `mindmap/` | 心智圖生成規則 | — |
| 💻 Coding | `coding/` | Code Understanding 各步驟提示（scan-project、gen-architecture、gen-api-spec、gen-error-mapping、gen-decisions、gen-test-payload、gen-standards、gen-faq、gen-overview、gen-feature-map、code-review） | — |
| 🔬 Domain AI | `domain-ai/` | 領域 AI 分析提示 | `spec/`、`test/`、`bug/`、`docs/`、`maintain/` |
| 📋 Project | `project/` | 專案管理（建專案、分析狀態、建議任務） | — |

**分類是固定的**（定義在 `ai-settings.mjs` 的 `CATEGORIES` 陣列），**分類內檔案完全動態** — 新增 `.md` 檔後 context-engine 會自動讀取（`getAISettings()` 動態掃目錄）。

### 2.3 檔案操作

| 操作 | UI 行為 | API |
| --- | --- | --- |
| 檢視 | 點檔名 → 載入內容顯示 | `GET /api/ai-settings/:category/:file` |
| 編輯 | 進入編輯模式 → 修改 → 儲存 | `PUT /api/ai-settings/:category/:file` |
| 新增 | 「新檔案」對話框 → 輸入檔名（必須 `.md` 結尾） | `POST /api/ai-settings/:category` |
| 刪除 | 檔案 → 刪除（有確認對話框） | `DELETE /api/ai-settings/:category/:file` |

**限制**：
- 檔名必須以 `.md` 結尾，含 `..` 的路徑會被拒（path traversal 防護）
- 僅有子分類的分類（skill-builder、domain-ai）允許 `sub/file.md` 形式的路徑，且 `sub` 必須在其 `subcategories` 清單內
- 建立已存在的檔名回 409

### 2.4 提示詞預覽（generic-preview）

不確定改了提示詞後最終送給 LLM 的長相？用 preview 端點看組裝結果：

```bash
# 組裝 chat target 的完整 system prompt（不含真的呼叫 LLM）
curl -X POST http://localhost:4097/api/ai-settings/generic-preview \
  -H "Content-Type: application/json" \
  -d '{"target": "chat", "prompt": "你的自訂問題"}'
```

回傳 `{ systemPrompt, userPrompt, model }`。`model` 顯示 `providerId/modelId`（可傳 `model` override）。

### 2.5 執行設定（agent-config.json）

`GET/PUT /api/ai-settings/agent-config` 讀寫 `data/ai-settings/agent-config.json`：

```json
{
  "maxTurns": 200,
  "timeoutSeconds": 0,
  "bashTimeoutSeconds": 300,
  "shellTimeoutMs": 600000
}
```

| 欄位 | 意義 | 預設 |
| --- | --- | --- |
| `maxTurns` | Agent loop 最大輪數 | 200 |
| `timeoutSeconds` | 整體任務 timeout（0 = 不限） | 0 |
| `bashTimeoutSeconds` | 單次 bash 指令 timeout | 300 |
| `shellTimeoutMs` | shell exec timeout（ms） | 600000 |

### 2.6 Provider 與模型偏好

- **Provider 設定**：`GET/PUT /api/ai-settings/providers` → `data/config/providers.json`（供應商清單與 active 標記）。UI 在 SettingsPage 的 Provider 分頁操作。
- **模型偏好**：`GET/PUT /api/user/preferences` → `data/config/user.json` 的 `preferences` 物件，key 為 feature 名、value 為 model override。PUT 採 merge 語意（只覆蓋傳入的 key）。

```bash
# 例：把 chat 功能的模型換成 openai/gpt-4o
curl -X PUT http://localhost:4097/api/user/preferences \
  -H "Content-Type: application/json" \
  -d '{"chat": "openai/gpt-4o"}'
```

### 2.7 Workspace 目錄

`GET/POST/DELETE /api/workspaces` 管理 `data/config/workspaces.json` 的 `directories` 清單 — 這是「AI 可存取的工作目錄」。GET 一律合併四個預設路徑（`data/apps`、`data/skills`、`data/knowledge`、`data/ai-settings`，存在者），清單去重。

```text
├── app-builder/               ← 📦 app-builder-rules.md
├── notes/                     ← 📝 system-prompt.md
├── mindmap/                   ← 🧠 system-prompt.md

└── app-exec/                  ← ⚠ 不在 CATEGORIES，UI 不可見（見下）
```

### 3.2 ⚠ 三個「隱形目錄」：agent-loop/、app-exec/ 與 skill-builder/generate/

磁碟上存在但**未列入 `CATEGORIES`**（或未列入 `subcategories`），因此 AI Settings UI 看不到、API CRUD 拒絕（回 404 Unknown category）：

| 目錄 | 內容 | 誰在用 |
| --- | --- | --- |
| `agent-loop/` | `system-prompt.md` | agent loop runtime 直接讀檔 |
| `app-exec/` | `system-prompt.md`、`data-analyst.md` | app 執行 runtime 直接讀檔 |
| `skill-builder/generate/` | `generate-prompt.md`、`generate-rules.md`、`output-rules.md` | `skills-api.mjs` 直接 `readFileSync` 讀取（skills-api.mjs:522） |

> skill-builder 分類的 `subcategories` 只列 `build`、`test` — `generate/` 子目錄存在於磁碟但不在清單內，掃描時被略過、CRUD 也會被拒。要改這三處提示詞只能直接編輯檔案（git 版控）。這是設計選擇：runtime 關銵提示詞不暴露在動態 CRUD 面上，避免誤刪導致 runtime 失效。

### 3.3 相關但不在 ai-settings/ 內的設定檔

| 檔案 | 內容 | 管理端點 |
| --- | --- | --- |
| `data/config/providers.json` | LLM 供應商與 API keys | `/api/ai-settings/providers` |
| `data/config/user.json` | 使用者檔案 + preferences | `/api/user/preferences` |
| `data/config/workspaces.json` | AI 可存取目錄 | `/api/workspaces` |

> 注意：providers/user/workspaces 實體檔案在 `data/config/`，**不在** `data/ai-settings/` — 端點掛在 ai-settings 路由下只是歷史沿革，備份兩個目錄都要含。

## 4. API 文件（14 端點）

Base：`/api/ai-settings`（除特別註明）

| # | Method | Path | 說明 |
| --- | --- | --- | --- |
| 1 | GET | `/api/ai-settings` | 列出全部分類（含即時檔案清單） |
| 2 | GET | `/api/ai-settings/:category` | 列出分類內檔案（含內容） |
| 3 | GET | `/api/ai-settings/:category/:file` | 讀單檔內容（支援 `sub/file.md`） |
| 4 | POST | `/api/ai-settings/:category` | 建立檔案 `{ file, content }` |
| 5 | PUT | `/api/ai-settings/:category/:file` | 更新檔案內容 |
| 6 | DELETE | `/api/ai-settings/:category/:file` | 刪除檔案 |
| 7 | GET | `/api/ai-settings/agent-config` | 讀 agent 執行設定 |
| 8 | PUT | `/api/ai-settings/agent-config` | 寫 agent 執行設定（whole-file replace） |
| 9 | GET | `/api/ai-settings/providers` | 讀 provider 設定 |
| 10 | PUT | `/api/ai-settings/providers` | 寫 provider 設定（whole-file replace） |
| 11 | POST | `/api/ai-settings/generic-preview` | 組裝任意 target 的最終 prompt 預覽 |
| 12 | POST | `/api/ai-settings/skill-builder/build` | Skill Builder CLI 組裝 context |
| 13 | POST | `/api/ai-settings/skill-builder/preview` | Skill Builder preview |
| 14 | GET/POST/DELETE | `/api/workspaces` | Workspace 目錄管理（另計） |

另有掛在本路由下的姊妹端點：`GET/PUT /api/user/preferences`（§2.6）、`GET /api/context/:target`（讀任意 target 的完整 system context，target 對照表見 `ai-settings.mjs` 的 `targetMap`）。

### 錯誤碼

| 狀態 | 情境 |
| --- | --- |
| 400 | 檔名非 `.md` 結尾、含 `..`、非法子分類路徑 |
| 404 | 未知分類、檔案不存在 |
| 409 | 建立已存在的檔案 |
| 500 | 檔案系統錯誤 |
